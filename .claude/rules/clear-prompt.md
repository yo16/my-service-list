# 切りのいいところで /clear を促す

コンテキストを小さく保つため、作業の切りのいいところで、ユーザーに `/clear` の実行を促す。`/clear` のあとのセッションは、beads の Issue と git だけを手がかりに再開する。そのため、促す前に、残タスクがすべて beads にあることと、git に未コミットの変更がないことを確かめる。

## 切りのいいところ

次のすべてに当てはまるときである。

- 頼まれた作業がひとまとまり完了し、コミットと push が済んでいる
- ユーザーへの質問や決断の依頼が残っていない
- 続きの作業が、いまの会話の内容を覚えていなくても、Issue の記述だけで始められる

作業の途中、ユーザーの返事を待っているとき、質疑応答だけのターンでは促さない。

## 促す前に確かめること

「停止するときに git と beads の状態を揃える」（`handoff.md`）の手順を済ませたうえで、次を上から順に行う。

1. **残タスクが beads にあるか確かめる**
   - `bd list --status=open` と `bd list --status=in_progress` を見る。
   - このセッションで出た残作業、後回しにしたこと、ユーザーに頼んだ作業が、すべて Issue になっているかを会話と照らし合わせる。足りないものは `bd create` で足す。
   - Issue の説明は、会話を読んでいない次のセッションが読んで着手できる内容にする。足りなければ `bd note` で補う。
2. **git に未コミットの変更がないか確かめる**
   - `git status` で、変更のあるファイルと未追跡のファイルがないことを確かめる。
   - 現在のブランチが、リモートより進んでいないこと（push していないコミットがないこと）を確かめる。
   - 残っていれば、git の運用ルールに従ってコミットし、push する。
3. **どちらかが満たせないときは促さない**
   - 壊れた状態でコミットできない変更が残っているときなどである。この場合は、何が残っているかを最後のメッセージに書く。

## 促し方

- 最後のメッセージの末尾に、`/clear` の実行を促す文を 1 つ書く。成果や残っていることの説明は、その前に書く。
- 確かめた結果は、「残っている作業は記録済みで、未コミットの変更はない」のように、ひとことで添える。Issue の ID や beads の操作は書かない。
- ユーザーにほかに頼むことがあるときは、実行する順に並べ、`/clear` を最後に置く。
